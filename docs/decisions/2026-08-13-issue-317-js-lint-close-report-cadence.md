# Issue #317 close — JS lint standard-compliance follow-up → custom ESLint config, verification deferred

## Context

Issue #317 was split out of #314's close (per `CLAUDE.md`'s "missed functionality becomes a NEW
issue" rule): the JS side of "lint Core Components and clear their errors" turned out to be 5,693
`standard` violation lines across all 59 JS files, not the "1 error" a stale checked-in report had
suggested.

## What happened across the loop

1. Step 2/3 review: presented three options — (a) mechanical `standard --fix` reformat of all 59
   files, (b) leave report-only/deferred, (c) swap the Mega-Linter JS flavor from
   `JAVASCRIPT_STANDARD` to plain ESLint with a custom config matching this repo's actual house
   style (double quotes, semicolons, no space before a named function's paren) instead of adopting
   Standard Style.
2. Human chose **(c)**, with two added requirements: keep the lint config flexible/tunable, and
   trim the Mega-Linter report to only what's necessary (not everything technically lintable).
3. Test PR waived (config/CI-tooling change, no user-facing AC to test against — same reasoning as
   `docs/decisions/2026-07-16-ci-tooling-defaults.md`).
4. Implemented and merged as [PR #320](https://github.com/mekhal/aidlc-radio-calico/pull/320)
   (`claude/issue-317-20260811-1558` → `develop`) and mirrored into `main` via
   [PR #321](https://github.com/mekhal/aidlc-radio-calico/pull/321) (human-merged):
   - New `.eslintrc.json` encoding the house style, plus a `globals` list resolving the
     `no-undef` false positives (`buildLogo`, `buildMenu`, etc. — genuine cross-file `<script>`
     globals `standard` couldn't see across files).
   - `.mega-linter.yml`: `DISABLE_LINTERS: [JAVASCRIPT_STANDARD, JAVASCRIPT_PRETTIER]` (not the
     originally-sketched `ENABLE_LINTERS`, which is a global whitelist across every language
     Mega-Linter runs — using it as planned would have silently dropped CSS's `stylelint` and
     YAML's linters too). `FILTER_REGEX_EXCLUDE` extended to drop `.claude/skills/` (Node-target
     skill-authoring scripts, not app code — a new finding from this issue's own investigation,
     directly satisfying the "only what's necessary" trim the human asked for).
   - One real house-style outlier found via manual audit (no local ESLint/network access in that
     session): a single-quoted test description in `tests/report-category-tagging.test.js`,
     switched to double quotes.
5. `@claude close` — human closed with **no score**, because the visible result (the checked-in
   lint report) had not yet changed, and asked for a new ticket to re-check later.

## Root cause of "the result hasn't changed yet"

`reports/lint/megalinter-report.html` (the file the human checked) is **only regenerated by the
weekly schedule job** in `.github/workflows/mega-linter.yml` (`cron: "0 3 * * 0"`, Sundays 03:00
UTC) — not by the `pull_request`/`push` triggers that ran on PR #320/#321. Those two triggers scan
and report to the PR/Actions log but never commit `reports/lint/megalinter-report.html` back to
the repo; only the weekly run's "Publish report to main" + "Sync report commit back into develop"
steps do that. As of this close (2026-08-13), the checked-in report file's last commit is
`e4fa9a1` (issue #340's close, unrelated to JS lint) and still shows the pre-fix state: `standard`
active with 1 reported error, not `JAVASCRIPT_ES`. This is expected, not a bug in PR #320/#321 —
the config change is live in `develop`/`main`, but its effect on the *checked-in report artifact*
won't be visible until the next Sunday run.
